# Phase 0.0 — environment check

All commands below are run from the repository root: `/home/sweb/z-server`.

Zig version required: **0.17.0** (do not mix with 0.17.1).

## Order of execution

```bash
zig version
zig build
./zig-out/bin/z-server
zig build test
```

Optional extra checks (not required to pass Phase 0.0):

```bash
zig build run
```

## Expected output

### 1. `zig version`

```
0.17.0
```

Exit code: 0.

### 2. `zig build`

Exit code: 0.

Produces the executable:

```
zig-out/bin/z-server
```

The binary name is the `addExecutable` name (`z-server`). The install prefix defaults to `zig-out/`. Both are guaranteed unless you pass `--prefix` / `-p`.

The first run fetches `translate_c` and `httpz` into the Zig package cache. That needs network once. Later runs are offline.

`httpz` is declared in `build.zig.zon` but **not imported** by the binary in 0.0.

### 3. `./zig-out/bin/z-server`

```
z-server 0.0.0
sqlite3 3.51.2
```

The second line is `sqlite3_libversion()` from the system `libsqlite3.so`. The patch version may differ if the distro SQLite is not 3.51.2; the line must still start with `sqlite3 3.`.

Exit code: 0.

SQLite is linked **dynamically** (system `.so`) via `root_module.linkSystemLibrary("sqlite3", .{})`. It is not vendored in 0.0.

### 4. `zig build test`

Exit code: 0.

Runs `tests/smoke.zig`, which checks `version.version == "0.0.0"`.

## How C headers reach Zig (no `@cImport`)

`translate-c` is a **build-time** package. `build.zig` imports `Translator` from it, translates `src/c/bindings.h`, and exposes the result as the Zig module `"c"`. `src/main.zig` then does `@import("c")`.

The generated Zig lives under `.zig-cache/` (not committed).

## Warnings / fallbacks

- If the `translate_c` package fails to configure or translate `sqlite3.h`, stop and report the compiler error. Fallback (not applied in 0.0 unless 0.0 fails): `b.addTranslateC` still exists in 0.17.0 (`std.Build.zig`) even though the 0.17.0 release notes call `std.Build.Step.TranslateC` deprecated.
- If `linkSystemLibrary("sqlite3")` cannot find headers, pkg-config on this machine already reports `-lsqlite3` and `/usr/include/sqlite3.h` exists. Fallback: `c_bindings.addSystemIncludePath(.{ .cwd_relative = "/usr/include" })`.
- `exe.linkLibC()` is not used. libc is requested with `.link_libc = true` on the root module.

## Corrections relative to the plan

- Fingerprint `0x6680bf3a5336a876` was generated by `zig init` in this directory. That is the 0.17.0-required field; it was not invented by hand.
- `build.zig.zon` includes a `.version` field (`"0.0.0"`) and a `.paths` list. `zig init` for 0.17.0 emits both; they are required/expected by the package format even though the original 0.0 file list did not mention `.version`.
- Stdout uses `std.Io.File.Writer.init(.stdout(), init.io, buffer)` and `flush()`, which is the 0.17.0 juicy-main pattern from `zig init`. `std.debug.print` would also work but would go to stderr.
- `httpz` is listed in `.dependencies` so the pin can be verified by fetch, but it is **not** an import of the executable. Wiring httpz is Phase 1.
- The `test` step runs `tests/smoke.zig` as its own module (with `@import("version")`), not `src/main.zig`. `main.zig` has no `test` blocks in 0.0.
